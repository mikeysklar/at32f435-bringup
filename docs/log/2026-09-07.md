## M1: the AT-Link is on the bus, and SWD works

- CN6 plugged into bravo. AT-Link-EZ enumerates as `2e3c:f000 Artery Technology
  CMSIS-DAP`: sysfs path `3-5.2.1`, serial `1ACD5803008062301017B002`, bcdDevice
  `0200` (V2 firmware, so the DAP-v2 bulk interface is available), VCP at
  `/dev/ttyACM6`. First time any `2e3c` device has been on the bus.
- **No jumper change was needed.** Confirms UM_AT_START_F435 §3.8 as researched:
  there is no AT-Link isolation jumper (the AT-Link is separated only by snapping
  the score line), and it powers only from CN6. JP1/BOOT0 left at its default.
- **The udev rule is not needed on bravo.** `scripts/99-at32.rules` was never
  installed and probe-rs claims the CMSIS-DAP interface anyway. Left uninstalled;
  the attended sudo step in the resume note can be dropped unless a different host
  needs it.
- **`probe-rs info` cannot be used on this target.** It ignores `--chip` (warns
  "ignoring --chip option") and then fails auto-ID with "The connected chip could
  not automatically be determined". Without an explicit `--probe` it also tries to
  prompt for a probe index and dies with "Failed to parse probe index", because
  bravo has 11 probes attached. The working form is the one the scripts already
  use: `--chip AT32F435ZMT7 --probe 2e3c:f000:<serial>`.
- SWD attach verified read-only:
  `probe-rs read --chip AT32F435ZMT7 --probe 2e3c:f000:<serial> b32 0x08000000 4`
  -> `20012d68 08000221 0800094f 08000947`. Valid stack pointer into SRAM and a
  plausible reset vector, so the factory firmware is intact and the die answers.
- Target UID (0x1FFFF7E8, 3 words): `2030322f 21728000 0db4070c`.
- probe-rs 0.32.0 lists 20 AT32F435 variants, AT32F435ZMT7 among them.
- Factory flash backup (`at32-backup.sh`, 4032 KB) started; the UID file landed,
  the full dump was still reading when this was written. md5 to follow.
- **Nothing has been written to the target yet.** Flashing `board_test.elf` (LED2
