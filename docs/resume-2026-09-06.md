Board on the bench is the AT-START-F435 (AT32F435ZMT7, LQFP-144, same die as the RMT7 on
our KiCad board). It was plugged into OTG1 (CN2) only; **the AT-Link-EZ debugger has never

## The one thing to do next

Plug **CN6 (AT-Link, the snap-off end)** into bravo, keep CN2 plugged. Expect
`2e3c:f000 CMSIS-DAP`. Then on bravo:

```sh
ssh bravo.local            # fallback: ssh -o HostKeyAlias=bravo.local 192.168.0.76
source ~/at32/bringup/scripts/bravo-env.sh
bash ~/at32/bringup/scripts/at32-find.sh            # ATLINK_PATH/SERIAL/TTY, never cache
# attended (sudo): sudo cp ~/at32/bringup/scripts/99-at32.rules /etc/udev/rules.d/ && sudo udevadm control --reload && sudo udevadm trigger
probe-rs info --chip AT32F435ZMT7
bash ~/at32/bringup/scripts/at32-backup.sh          # factory image + UID + md5 -> ~/at32/backups/
bash ~/at32/bringup/scripts/at32-flash.sh ~/at32/tinyusb/examples/device/board_test/_build/at_start_f435/board_test.elf   # blinky PD13
```
Then M2: flash `cdc_msc` built with default RHPORT (device on CN3/OTG2) as baseline, then
rebuild with `RHPORT_DEVICE=0` on branch `tinyusb-rhport-override` and enumerate on CN2.
Then M3: `~/at32/build-module/cdc_acm/zephyr/zephyr.hex` (module build) or the fork build
`~/at32/zephyr-at32-ws/build-cdc`. Then M4: `~/at32/circuitpython/ports/zephyr-cp/build-artery_at_start_f435/firmware.hex`.

Second probe path if probe-rs misbehaves: `~/.local/openocd-at32/bin/openocd -f interface/atlink_dap_v2.cfg -f target/at32f435xM.cfg`.
Recovery: JP1 (BOOT0) to VDD, reset -> ROM DFU `2e3c:df11` on CN2, `dfu-util -a 0 -d 2e3c:df11 --dfuse-address 0x08000000 -D fw.bin`.

## Findings worth remembering (details in tracker issues)

- TinyUSB BSP hard-codes device on OTG2 (PB14/15 = CN3); we standardize on OTG1 (CN2).
- `make flash` for every at32 family is a dangling `flash-atlink` target.
- ArteryTek OpenOCD fork needs `--disable-werror` on GCC 13; upstream OpenOCD has no
  F435 M-density and no release with artery.c at all.
- ArteryTek Zephyr fork needs SDK exactly 0.17.4 (installed `~/zephyr-sdks/`); `west sdk
  install -d $HOME` breaks, use a subdir and run `setup.sh -t arm-zephyr-eabi -c` by hand.
- Fork board dts LEDs are ACTIVE_HIGH; TinyUSB drives PD13 active-low. Verify on hardware.
- Fork dts flash partitions overlapped; CP overlay rebuilt them. CIRCUITPY partition
  crosses the 0x200000 bank boundary: untested in flash_at32.c.
- zephyr-cp generator ignored dwc2 `num-in-eps/num-out-eps` -> 0 endpoints for every dwc2
  board (tracker #16, upstream candidate).
- Artery periph lib `usb_disconnect(otg_global_type*)` collides with CP `usb_disconnect(void)`;
  hidden in the module's soc.h.
- HAL license: BSD-3 repo vs Artery-only file headers (tracker #14); hal_at32 is Apache-2.0.
